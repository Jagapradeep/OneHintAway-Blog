One Hint Away (@onehintaway). Clues: **numbers next to each other** (a subarray or substring) and **a fixed length k**.

Worked example: **the biggest sum of k numbers in a row**, the GeeksforGeeks problem "Max Sum Subarray of size K".

## The walk

`nums = [2, 1, 5, 1, 3, 2]`, `k = 3` returns `9`.

| window | in | out | sum |
|---|---|---|---|
| [2, 1, 5] | first window | | 8 |
| [1, 5, 1] | 1 | 2 | 7 |
| [5, 1, 3] | 3 | 1 | **9** |
| [1, 3, 2] | 2 | 5 | 6 |

**Who leaves?** When `nums[i]` joins, `nums[i - k]` leaves. At `i = 3`, index `3 - 3 = 0` drops out, so the window stays exactly `k` long.

## Pseudocode

```
function maxSum(nums, k):
    total = 0
    for i from 0 to k - 1:
        total = total + nums[i]
    best = total
    for i from k to length(nums) - 1:
        total = total + nums[i] - nums[i - k]
        best = max(best, total)
    return best
```

**The trap:** taking away the wrong number. Subtract `nums[i - k + 1]` by mistake and at `i = 3` you remove the 1 that is still inside the window. The sums come out 8, 8, 6, 7 and you return 8 instead of 9. The number that leaves is always `nums[i - k]`.

## Java

```java
class Solution {
    // O(n) time, O(1) space
    public int maxSum(int[] nums, int k) {
        int total = 0;
        for (int i = 0; i < k; i++) {
            total = total + nums[i];
        }
        int best = total;
        for (int i = k; i < nums.length; i++) {
            total = total + nums[i] - nums[i - k];
            best = Math.max(best, total);
        }
        return best;
    }
}
```

If a platform allows very large numbers or very long arrays, the sum can pass the 32-bit limit (about 2.1 × 10^9). Use `long` in Java and `long long` in C++ there.

## Complexity

| Version | Time | Extra space |
|---|---|---|
| Re-add every window | O(n·k) | O(1) |
| Sliding window | O(n) | O(1) |

## How it was tested
